# 在线反馈设计

本文汇总用户已确认并授权实施的产品规则。数据库及本地代码已接入；验证范围见文末。

## 已确认规则

- 设置中提供“在线反馈”入口。问题和消息允许未登录用户查看；创建问题和发言要求登录。公开昵称及必要身份标识，不展示头像，不公开邮箱等认证资料；无昵称时不回退到邮箱。
- 使用 Supabase 账号 UUID 标识用户；超级管理员使用独立表管理，首个指定账号为“谢必安”，已核实唯一 Auth UUID 并写入管理员表。
- 问题包含必填标题和必填描述。第一版搜索标题和描述；已登录且未受限制的用户可以参与讨论。
- 问题列表分页，支持全部/自己创建、搜索、创建时间/最近发言时间升降序。
- 问题有开启、不予处理、已完成三种状态，均允许讨论。问题创建者和超级管理员可变更状态及重新开启。
- 另设锁定讨论字段，锁定后仅问题创建者和超级管理员可以发言。
- 问题创建者和超级管理员可修改标题、描述。第一版不提供消息编辑、问题删除和创建者身份转让。
- 创建者可在自己的问题内禁言普通用户；超级管理员可执行单个问题或全局禁言。全局禁言同时禁止创建问题。创建者不能禁言超级管理员。禁言手动解除，不设到期时间。
- 问题创建者不能被任何人在其创建的问题内禁言，只能被全局禁言；在其他人创建的问题内，其身份仍是普通参与者，可受问题内禁言限制。
- 全局禁言优先于创建者发言资格，包括其自己的问题；被禁言的创建者仍可修改已有问题、变更状态、锁定讨论和撤回消息，不能解除自己的全局禁言。超级管理员不受禁言影响。
- 标题 1～100 字且单行，问题描述和消息 1～1000 字，拒绝纯空白；描述和消息允许换行。字符计数以 Dart 的 text.characters.length 为准。原样展示文本，不解析 HTML/Markdown，网址可点击。
- 普通消息发送者可在 5 分钟内撤回自己的消息；问题创建者和超级管理员可随时撤回任意普通用户消息。超级管理员消息仅该发送者本人可随时撤回，其他管理员也不可撤回。
- 消息是否受超级管理员身份保护，仅按发送者当前身份判断，不保存发送时角色作为保护依据；用户成为管理员后历史消息随之受保护，移除管理员身份后历史消息不再受该保护。
- 锁定讨论和禁言不影响撤回权限；普通用户仍可在服务器接收消息后不超过 300 秒时撤回自己的消息。
- 撤回清除正文、提及用户列表和 @ALL 标记，保留消息 ID、发送者、时间及撤回记录；管理员可查看撤回操作者。撤回占位文字为“该消息已被撤回”。
- 长按消息可回复，回复只关联原消息 ID，不复制正文；原消息撤回后，回复引用显示“该消息已被撤回”。回复不自动提及对方。
- 每条消息最多回复同一问题内的一条消息，不允许对已撤回消息发起新回复。点击回复引用时，若目标不在当前列表，显示 loading 并连续补齐所有中间消息，直到目标及时间上更早的 10 条；不足则加载到问题起点。显示已加载数量并允许取消。随后使用 SuperListView 的 animateToItem 定位，设置 precalculateTargetItemCount: true。
- 提及用户使用独立列表字段，只能选择曾在该问题发言的用户；@ALL 使用独立字段，所有有权发言的用户均可使用。不产生实时提醒、未读提醒或系统推送。
- 输入区提供“@”按钮，打开可搜索、分页的发言者列表，并提供“所有人”选项。选择结果以可移除标签展示，消息正文之外单独展示提及信息；用户名单去重。允许同时 @ALL 和单独用户，选择 @ALL 不清空用户名单。仅有提及而正文为空时不可发送。
- 各列表使用 SuperListView。消息按时间倒序分页，默认 30；用户可设置消息分页大小为整数 1～114，作为本机全局设置持久保存。修改后下一次分页请求生效，不清空当前消息；问题列表仍固定每页 30 条。
- 问题列表每页 30 条，默认全部问题、最近发言时间降序。搜索、筛选和排序共同生效。实时更新已有条目内容，排序或结果集合变化时显示“列表有更新”，点击后刷新重排；重连及从详情返回时直接刷新。
- 最近发言时间不会因撤回而回退，无消息时使用问题创建时间；修改标题、描述、状态不算发言，相同时间使用唯一 ID 稳定排序。
- 在线反馈数据仅在模块打开期间处理；进入详情后暂停列表实时处理，仅维护当前问题。返回列表时刷新列表并销毁详情消息及订阅；退出模块后清空模块数据。
- 应用进入后台暂停反馈订阅；回前台按重连规则恢复。全局消息分页大小作为设置保留。
- 重连时，列表页刷新问题列表；详情页补齐最新消息到内存已有消息之间的区间，不受单页大小限制。不批量核对已加载旧消息的撤回状态，断线期间的旧消息撤回可能在重新进入问题前仍显示旧内容。重连时刷新问题标题、描述、状态、锁定及当前权限；所有写入始终由服务器按当前权限判断。
- 退出问题后不持久化消息，下次进入重新加载。
- 问题消息列表中点击用户可进入其个人页面，普通用户也可查看。公开最后登录时间，is_pro 为真时向所有人展示“P”，点击弹出简短解释。隐藏超级管理员身份标记；超级管理员的个人页面、最后登录时间及 P 标记仍按普通用户规则展示，管理权限不受影响。
- 个人页面是当前问题的子页面；打开时保留问题消息、滚动位置、输入内容及订阅，返回后继续阅读。退出问题时销毁这些数据，退出在线反馈模块时一起关闭个人页面。
- 个人页面携带来源问题上下文并显示问题标题。问题创建者可禁言/解除该用户在当前问题的禁言；超级管理员还可全局禁言/解除以及开启/关闭 Pro；普通用户只查看。撤回消息使用消息长按菜单。
- 超级管理员可修改任何其他用户现有的 is_pro 字段，包括其他超级管理员；该入口不修改自己。支持授予和取消，无有效期；提交前展示目标及修改结果供确认，服务器记录操作者、目标、修改前后值和时间。Pro 与超级管理员身份独立，不赋予聊天管理权限。
- 超级管理员名单仅通过数据库管理，不提供应用内增删入口。
- 同一普通账号每 3 秒可发送一条消息、每 60 秒可创建一个问题，超级管理员免除。发送失败保留输入供手动重试，使用相同发送标识避免重复消息。
- 新消息到达时，位于最新位置则自动跟随；阅读历史时保持位置并显示“有 N 条新消息”，点击回到最新位置。本人发送成功后滚动到最新消息；该计数仅属于当前阅读会话，不产生持久未读记录或推送。

## 权限表

问题创建者在其创建的问题中适用创建者权限，在其他问题中适用普通参与者权限；同一用户拥有多种身份时，超级管理员权限优先。

| 操作 | 未登录访客 | 普通参与者 | 当前问题创建者 | 超级管理员 |
| --- | --- | --- | --- | --- |
| 查看公开问题、消息、个人页面 | 可以 | 可以 | 可以 | 可以 |
| 创建问题 | 不可以 | 未全局禁言时 | 未全局禁言时 | 可以 |
| 未锁定问题内发言 | 不可以 | 未受问题内/全局禁言时 | 未全局禁言时 | 可以 |
| 锁定问题内发言 | 不可以 | 不可以 | 未全局禁言时 | 可以 |
| 修改标题、描述、状态和锁定 | 不可以 | 不可以 | 当前问题 | 全部问题 |
| 问题内禁言/解除 | 不可以 | 不可以 | 当前问题的普通参与者 | 任意问题的普通参与者 |
| 全局禁言/解除 | 不可以 | 不可以 | 不可以 | 非超级管理员用户 |
| 撤回本人消息 | 不可以 | 发送后不超过 300 秒 | 自己问题内任意时间，其他问题内不超过 300 秒 | 任意时间 |
| 撤回他人消息 | 不可以 | 不可以 | 当前问题内、发送者当前非超级管理员 | 发送者当前非超级管理员 |
| 修改他人的 is_pro | 不可以 | 不可以 | 不可以 | 可以，包括其他超级管理员 |
| 应用内增删超级管理员 | 不可以 | 不可以 | 不可以 | 不可以，仅数据库管理 |

锁定、禁言和频率限制均不扩大撤回权限；is_pro 不赋予任何聊天管理权限。

## 实施依据

- 已核实“谢必安”账号的唯一 Auth UUID，不按昵称授予权限。
- 已通过 Supabase MCP 核实线上表结构、RLS 和触发器；保留既有资料表的普通用户权限，并增加受控的 Pro 管理路径。
- 公开资料避免复用现有昵称为空时回退邮箱的展示逻辑，也不能因公开最后登录时间和 P 标记而暴露认证资料。
- 服务器对内容长度的校验须与 Dart characters 的字素簇计数一致，不能用数据库普通字符串长度直接代替。


## 实现与验证

设置入口对应 `/online_feedback`。反馈页面使用 GetView、GetBuilder 和 Bindings，接入已有 Navigator(id: 1)、ThemedGetPageRoute、ListenPopMiddleware、addAndCleanReapeatRoute 与 routerPop。问题列表、消息列表和个人页面分别为真实命名路由，通过 FeedbackPageArgs 传入参数和独立的控制器标签。

列表和每个问题分别持有路由作用域的 FeedbackController（GetxController），由绑定启动、onClose 释放。问题页覆盖列表时暂停列表处理，返回时刷新；个人页通过专属的 FeedbackProfileController 借用来源问题控制器，保留消息、草稿、阅读位置及订阅。个人页关闭只释放自己的绑定，问题页关闭才释放消息，再次进入重新创建控制器并加载。

反馈路由观察者区分“进入自己的个人页面”和“被其他页面覆盖”。前者保留问题订阅，后者暂停；应用前后台状态与路由可见性分别记录，避免后台返回时错误恢复被其他页面覆盖的列表。异步请求按页面代次丢弃过期结果。

数据库使用公开只读的 feedback_issues、feedback_messages 和 feedback_events；feedback_superadmins 不授予 API 角色读写权限，禁言和审计位于不暴露的 feedback_private schema。写入只允许通过 feedback_action，由服务器验证当前身份、禁言、锁定、内容、引用、限频及撤回条件。普通用户无法通过直接表写入绕过规则。

公开资料 RPC 仅返回 UUID、昵称、最后登录时间和 is_pro；不读取邮箱。读分页 RPC 使用游标避免相同时间排序不稳定。用于公开资料和当前用户权限的 SECURITY DEFINER RPC 是有意授权的接口，固定 search_path 并限制返回字段；安全顾问中此类“可执行 SECURITY DEFINER”提示不等同于越权写入。既有项目的其他安全顾问提示不在此次改动范围。

服务器字符计数由项目固定的 characters 1.4.1 生成同一分类表和前向状态机。生成脚本为 tools/generate_feedback_graphemes.dart；Dart 与 Unicode 许可位于 supabase 目录。为限制异常巨大组合字符输入，服务器另有每个文本字段 256 KiB 的请求内容上限。

迁移文件版本与 Supabase MCP 已执行的迁移历史一致；本仓库只新增本功能迁移，既有数据库历史仍在远端。不要在现有项目上重新执行已应用的迁移；全新项目需先具备既有 users 资料表和 Auth 结构，并替换首个管理员 UUID。

以下为实现期间已执行的历史验证记录。相关测试文件和检查脚本已按要求删除，以下结果仅代表当时验证，不提供可直接重跑的测试入口：

- 数据库事务中模拟角色，验证了写入权限、限频、幂等、禁言、撤回、管理员变更及 Pro 审计，结束后回滚了全部测试数据。
- 验证了游标分页、114 上限、字素簇长度、严格字符串、提及、跨问题回复、撤回和当前身份保护，结束后回滚了全部测试数据。字符计数与 Dart 和 Unicode 官方语料对照的 1093 个样例全部一致。
- 控制器测试验证了超过一页的新消息补齐、连续加载引用及前十条、过期请求隔离、个人页面保留及退出释放、稳定问题分页游标。
- 页面测试使用真实 Get 命名路由、绑定及返回逻辑，验证了 390×844 页面切换、个人页下的消息及草稿保留、问题页退出释放和重新进入加载，以及新消息到达时历史消息的可视位置保持。
- 使用现有公开客户端配置，只读验证了真实匿名 RPC 和三个反馈表的 Realtime 订阅。

尚未进行真实设备、多账号客户端交互或网络切换的人工验收。数据库回滚测试和真实匿名订阅测试不等同于该项验收。
